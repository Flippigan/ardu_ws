# Multi-Drone 3D Formation Control Project Plan

## Project Overview

**Objective**: Develop a system to control multiple drones simultaneously to form 3D patterns in the sky, starting with sphere formations, while ensuring collision avoidance and flight safety.

**Target Pattern**: 3D Sphere formation with 5-16 drones
**Base Platform**: ArduPilot ROS2 workspace with Gazebo simulation

---

## Current Architecture Analysis

### Scaling Requirements from Single to Multi-Drone

- **Communication**: Current single namespace `/ap/*` → Multiple namespaces `/ap_N/*`
- **Simulation**: Single ArduPilot SITL → Multiple SITL instances (ports 5760, 5761, 5762...)
- **Models**: Single Iris model → Fleet of uniquely identified vehicles
- **Control**: Single circle_detector → Formation controller + individual drone agents
- **Safety**: Basic flight safety → Multi-drone collision avoidance system

## Formation Control & Collision Avoidance Algorithms

### Recommended Control Algorithms

1. **Virtual Structure Approach** (Primary for sphere formation)
   - Define sphere as virtual rigid body in 3D space
   - Each drone assigned to specific point on sphere surface
   - Spherical coordinates: `(r, θ, φ)` where r = sphere radius
   - Formation moves as single entity with individual drone compliance

2. **Centralized Collision Detection & Prevention**
   - Ground station maintains real-time 3D map of all drone positions
   - Trajectory prediction algorithms detect potential collisions
   - Preemptive path modification before conflicts arise
   - Emergency stop capability with <100ms response time

3. **Centralized Safety Monitoring**
   - Ground station monitors all drone positions continuously
   - Real-time collision detection and prevention
   - Emergency stop capability for individual or all drones

## System Architecture: Fully Centralized Control

### Architecture Design

```
Ground Control Station (Centralized)
├── Formation Commander (sphere patterns, waypoints)
├── Safety Monitor (real-time collision detection)
├── Emergency Stop Controller (immediate drone halt)
├── Fleet Coordinator (assigns drone positions)
└── Mission Planner (formation maneuvers)

Individual Drones (Simple Agents)
├── Position Reporter (sends GPS/pose to ground station)
├── Command Receiver (receives waypoints from ground)
├── Basic Flight Controller (follows waypoints)
└── Emergency Stop Receiver (immediate halt capability)
```

### Communication Flow
- **Command**: Ground Station → Drones (target positions, waypoints, emergency stops)
- **Telemetry**: Drones → Ground Station (position, velocity, status) 
- **Safety**: Ground Station monitors ALL drone positions, no inter-drone communication

### Benefits
- Complete centralized control and safety oversight
- Simplified drone software (no complex collision avoidance onboard)
- Deterministic safety - ground station has global view of all drones
- Easier debugging and monitoring - single point of control
- Reduced communication complexity - star topology instead of mesh

## Mathematical Models for 3D Sphere Formation

### Core Sphere Equations

```python
# Sphere parameterization in spherical coordinates
def sphere_point(center, radius, theta, phi):
    """
    center: [x, y, z] - sphere center position
    radius: float - sphere radius  
    theta: float - azimuthal angle [0, 2π]
    phi: float - polar angle [0, π]
    """
    x = center[0] + radius * sin(phi) * cos(theta)
    y = center[1] + radius * sin(phi) * sin(theta)  
    z = center[2] + radius * cos(phi)
    return [x, y, z]
```

### Drone Distribution Strategies

1. **Fibonacci Spiral Distribution** (Optimal for uniform coverage):
   ```python
   for i in range(N_drones):
       theta_i = 2 * pi * i / golden_ratio
       phi_i = arccos(1 - 2*i/N_drones)
   ```

2. **Geodesic Distribution** (Structured, expandable):
   - Based on icosahedron subdivision
   - Natural hierarchy for adding/removing drones

### Formation Dynamics
- **Translation**: `sphere_center(t) = sphere_center(0) + velocity * t`
- **Rotation**: `theta_i(t) = theta_i(0) + angular_velocity * t` 
- **Scaling**: `radius(t) = radius(0) * scale_factor(t)`
- **Morphing**: Interpolation between sphere and other 3D shapes

## Multi-Layered Collision Avoidance & Safety Systems

### Three-Layer Safety Architecture

1. **Strategic Layer (Formation Planning)**
   ```python
   # Minimum separation constraints in formation planning
   def generate_sphere_formation(num_drones, radius, min_separation=5.0):
       positions = fibonacci_sphere_distribution(num_drones, radius)
       return optimize_positions(positions, min_separation_constraint)
   ```

2. **Tactical Layer (Real-time Safety Monitoring)**
   ```python
   # Centralized collision detection and prevention
   class SafetyMonitor:
       def __init__(self):
           self.safety_radius = 3.0  # meters
           self.warning_radius = 6.0  # meters
           self.prediction_time = 2.0  # seconds ahead
           
       def check_all_collisions(self, drone_positions, drone_velocities):
           collision_risks = []
           for i in range(len(drone_positions)):
               for j in range(i+1, len(drone_positions)):
                   risk = self.predict_collision_risk(i, j, drone_positions, drone_velocities)
                   if risk > 0:
                       collision_risks.append((i, j, risk))
           return collision_risks
           
       def execute_emergency_stop(self, drone_ids):
           # Send immediate stop commands to at-risk drones
           for drone_id in drone_ids:
               self.send_emergency_stop(drone_id)
   ```

3. **Emergency Layer (Ground Station Control)**
   - **Immediate Stop**: Ground station sends emergency halt to specific drones
   - **Emergency Landing**: Controlled descent to nearest safe landing zone
   - **Return to Launch**: Ground station guides drones back to launch positions
   - **Formation Abort**: Ground station dissolves formation, switches to individual control

### Safety State Machine
```
NORMAL → CAUTION → WARNING → EMERGENCY
   ↓        ↓         ↓          ↓
Formation → Adjust → Avoid → Stop/RTL
Control    Speed    Maneuver   
```

### Fault Recovery Scenarios
- **Drone Loss**: Ground station reconfigures formation with remaining drones
- **Communication Loss**: Drones enter autonomous hover/RTL mode, no collision avoidance
- **Ground Station Failure**: All drones automatically enter emergency landing sequence
- **Network Latency**: Ground station compensates with predictive algorithms
