## Executive Summary

This document provides the **definitive reference** for all DDS topics and services available in the multi-drone formation control system. Based on live system verification, all topic and service namespaces follow a simple `/ap_N/` pattern where N is the instance ID (1-5).

### **Namespace Structure (VERIFIED)**

**All topics and services use clean ROS2 namespaces:**
- **Topics**: `/ap_N/...` (e.g., `/ap_1/pose/filtered`)
- **Services**: `/ap_N/...` (e.g., `/ap_1/arm_motors`)

**No additional prefixes required.** The micro-ROS agent handles DDS internal routing (`rt/`, `rs/`, `rq/`, `rr/`) transparently, presenting clean ROS2 interfaces.

### **Verified Commands**

```bash
# Topic subscription (VERIFIED WORKING)
ros2 topic echo /ap_1/pose/filtered --once

# Service call (VERIFIED WORKING)
ros2 service call /ap_1/mode_switch ardupilot_msgs/srv/ModeSwitch "{mode: 4}"
```

## Formation Control Integration

### **Essential Topics for Multi-Drone Pattern Formation**

#### **Position Feedback** (30 Hz)
```python
# Subscribe to local position (NED frame, relative to GPS origin)
topic = f'/ap_{instance_id}/pose/filtered'
msg_type = geometry_msgs.msg.PoseStamped
```

**Usage**: Primary position feedback for formation control algorithms. Provides high-rate local position in NED (North-East-Down) frame.

#### **GPS Position Feedback** (30 Hz)
```python
# Subscribe to global GPS position
topic = f'/ap_{instance_id}/geopose/filtered'
msg_type = geographic_msgs.msg.GeoPoseStamped
```

**Usage**: Global position reference for formation center positioning and GPS-based waypoint navigation.

#### **Velocity Feedback** (30 Hz)
```python
# Subscribe to velocity (linear and angular)
topic = f'/ap_{instance_id}/twist/filtered'
msg_type = geometry_msgs.msg.TwistStamped
```

**Usage**: Velocity feedback for trajectory prediction and collision avoidance algorithms.

#### **Vehicle Status** (10 Hz)
```python
# Subscribe to vehicle status
topic = f'/ap_{instance_id}/status'
msg_type = ardupilot_msgs.msg.Status
```

**Usage**: Monitor armed state, flight mode, and system health.

## Formation Control Code Examples

### **Example 1: Multi-UAV Position Monitoring**

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import PoseStamped

class FormationMonitor(Node):
    def __init__(self):
        super().__init__('formation_monitor')
        self.positions = {}

        # Subscribe to all UAV positions
        for instance_id in range(1, 6):
            topic = f'/ap_{instance_id}/pose/filtered'
            self.create_subscription(
                PoseStamped,
                topic,
                lambda msg, iid=instance_id: self.position_callback(msg, iid),
                10
            )
            self.get_logger().info(f'Subscribed to {topic}')

    def position_callback(self, msg, instance_id):
        pos = msg.pose.position
        self.positions[instance_id] = (pos.x, pos.y, pos.z)
        self.get_logger().info(
            f'UAV_{instance_id}: [{pos.x:.2f}, {pos.y:.2f}, {pos.z:.2f}]'
        )

def main():
    rclpy.init()
    node = FormationMonitor()
    rclpy.spin(node)
    rclpy.shutdown()

if __name__ == '__main__':
    main()
```

### **Example 2: Swarm Takeoff Sequence**

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from ardupilot_msgs.srv import ArmMotors, ModeSwitch, Takeoff

class SwarmTakeoff(Node):
    def __init__(self):
        super().__init__('swarm_takeoff')
        self.instance_ids = [1, 2, 3, 4, 5]

        # Create service clients
        self.arm_clients = {}
        self.mode_clients = {}
        self.takeoff_clients = {}

        for iid in self.instance_ids:
            self.arm_clients[iid] = self.create_client(
                ArmMotors, f'/ap_{iid}/arm_motors')
            self.mode_clients[iid] = self.create_client(
                ModeSwitch, f'/ap_{iid}/mode_switch')
            self.takeoff_clients[iid] = self.create_client(
                Takeoff, f'/ap_{iid}/experimental/takeoff')

    async def execute_swarm_takeoff(self, altitude=10.0):
        # Step 1: Set all to GUIDED mode
        for iid in self.instance_ids:
            req = ModeSwitch.Request()
            req.mode = 4  # GUIDED
            await self.mode_clients[iid].call_async(req)
            self.get_logger().info(f'UAV_{iid} set to GUIDED mode')

        # Step 2: Arm all motors
        for iid in self.instance_ids:
            req = ArmMotors.Request()
            req.arm = True
            await self.arm_clients[iid].call_async(req)
            self.get_logger().info(f'UAV_{iid} armed')

        # Step 3: Command takeoff
        for iid in self.instance_ids:
            req = Takeoff.Request()
            req.alt = altitude
            await self.takeoff_clients[iid].call_async(req)
            self.get_logger().info(f'UAV_{iid} takeoff commanded')
```

### **Example 3: Formation Velocity Controller**

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TwistStamped, PoseStamped
import numpy as np

class FormationController(Node):
    def __init__(self):
        super().__init__('formation_controller')
        self.instance_ids = [1, 2, 3, 4, 5]
        self.positions = {}
        self.target_positions = {}

        # Publishers for velocity commands
        self.cmd_vel_pubs = {}
        for iid in self.instance_ids:
            self.cmd_vel_pubs[iid] = self.create_publisher(
                TwistStamped, f'/ap_{iid}/cmd_vel', 10)

        # Subscribers for position feedback
        for iid in self.instance_ids:
            self.create_subscription(
                PoseStamped,
                f'/ap_{iid}/pose/filtered',
                lambda msg, i=iid: self.position_callback(msg, i),
                10
            )

        # Control loop timer (20 Hz)
        self.create_timer(0.05, self.control_loop)

    def position_callback(self, msg, instance_id):
        pos = msg.pose.position
        self.positions[instance_id] = np.array([pos.x, pos.y, pos.z])

    def control_loop(self):
        # Simple proportional controller for formation
        K_p = 0.5  # Proportional gain

        for iid in self.instance_ids:
            if iid not in self.positions or iid not in self.target_positions:
                continue

            # Calculate position error
            error = self.target_positions[iid] - self.positions[iid]

            # Calculate velocity command (proportional control)
            velocity = K_p * error

            # Limit maximum velocity
            max_vel = 2.0  # m/s
            velocity_mag = np.linalg.norm(velocity)
            if velocity_mag > max_vel:
                velocity = velocity * (max_vel / velocity_mag)

            # Publish velocity command
            msg = TwistStamped()
            msg.twist.linear.x = velocity[0]
            msg.twist.linear.y = velocity[1]
            msg.twist.linear.z = velocity[2]
            self.cmd_vel_pubs[iid].publish(msg)
```

## Common Flight Modes (ArduCopter)

| Mode Number | Mode Name | Description |
|-------------|-----------|-------------|
| 0 | STABILIZE | Manual flight with attitude stabilization |
| 2 | ALT_HOLD | Manual flight with altitude hold |
| 3 | AUTO | Autonomous mission execution |
| 4 | GUIDED | External position/velocity control |
| 5 | LOITER | Position hold (GPS) |
| 6 | RTL | Return to launch |
| 9 | LAND | Autonomous landing |
| 13 | SPORT | Manual flight with aggressive tuning |
| 16 | POSHOLD | Position hold (GPS + optical flow) |

**For formation control**, use **GUIDED mode (4)** which enables:
- `/ap_N/cmd_vel` velocity commands
- `/ap_N/cmd_gps_pose` waypoint commands
- External autonomous control

## Troubleshooting

### **Services Not Responding**

**Problem**: Service calls timeout or return no response

**Solutions**:
1. Verify service exists:
   ```bash
   ros2 service list | grep "/ap_1"
   ```

2. Check service type matches:
   ```bash
   ros2 service type /ap_1/arm_motors
   # Expected: ardupilot_msgs/srv/ArmMotors
   ```

3. Ensure ArduPilot is in appropriate mode:
   - Some services require specific flight modes
   - Arming requires pre-arm checks to pass

4. Check micro-ROS agent logs for errors

### **Velocity Commands Not Working**

**Problem**: Publishing to `/ap_N/cmd_vel` has no effect

**Solutions**:
1. Verify vehicle is in GUIDED mode:
   ```bash
   ros2 topic echo /ap_1/status --once
   # Check mode field = 4
   ```

2. Verify vehicle is armed:
   ```bash
   ros2 topic echo /ap_1/status --once
   # Check armed field = true
   ```

3. Check command is being published:
   ```bash
   ros2 topic hz /ap_1/cmd_vel
   ```

4. Verify correct frame (body frame, NED convention):
   - X = forward (positive = forward)
   - Y = right (positive = right)
   - Z = down (positive = down)
