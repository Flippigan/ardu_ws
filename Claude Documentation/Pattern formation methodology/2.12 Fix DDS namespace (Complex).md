# ArduPilot DDS Instance Namespacing Methodology
**Multi-Instance SITL Pattern Formation Control**

## Executive Summary

This document presents a comprehensive methodology for modifying ArduPilot's DDS (Data Distribution Service) source code to enable individual instance namespacing for multi-UAV pattern formation control. The approach focuses on **source-level modifications** to the ArduPilot DDS client to dynamically generate unique topic and service names for each SITL instance, enabling simultaneous control of multiple vehicles through distinct ROS2 namespaces.

**Document Version:** 1.0
**Target ArduPilot Version:** 4.5+
**Focus Area:** `AP_DDS` Library Source Code Modifications
**Implementation Scope:** C++ Source Code Only

---

## Problem Statement

### Current Limitation
ArduPilot's DDS implementation uses **hardcoded topic names** in `AP_DDS_Topic_Table.h` and `AP_DDS_Service_Table.h`, causing all SITL instances to publish/subscribe to identical topic names:

```cpp
// Current Implementation - All instances use same topics
.topic_name = "rt/ap/pose/filtered",
.topic_name = "rt/ap/cmd_vel",
.service_name = "rs/ap/arm_motorsService",
```

This creates **namespace collision** where multiple vehicles cannot be individually controlled, as they all listen to the same command topics and publish to the same status topics.

### Required Solution
**Dynamic topic/service name generation** based on SITL instance ID, producing unique namespaces:

```cpp
// Target Implementation - Instance-specific topics
Instance 0: "rt/ap_0/pose/filtered", "rt/ap_0/cmd_vel"
Instance 1: "rt/ap_1/pose/filtered", "rt/ap_1/cmd_vel"
Instance 2: "rt/ap_2/pose/filtered", "rt/ap_2/cmd_vel"
```

## Phase 2: Dynamic Name Generation

### 2.1 Instance Detection Logic

**File:** `AP_DDS_Client.cpp`

```cpp
// Add new method after constructor
uint8_t AP_DDS_Client::detect_instance_id()
{
    // Use explicit instance ID if set
    if (instance_id >= 0) {
        return static_cast<uint8_t>(instance_id.get());
    }

    // Auto-detect from SYSID_THISMAV parameter
    AP_Param *param = AP_Param::find("SYSID_THISMAV", nullptr);
    if (param != nullptr) {
        uint8_t sysid = static_cast<AP_Int8*>(param)->get();
        // Convert SYSID to instance (handle multi-instance SITL pattern)
        return (sysid > 1) ? (sysid - 1) : 0;
    }

    return AP_DDS_DEFAULT_INSTANCE_ID;
}

void AP_DDS_Client::generate_topic_name(char* buffer, size_t buffer_size,
                                       const char* base_name, uint8_t instance)
{
    // Replace "rt/ap/" with "rt/ap_N/" pattern
    if (strncmp(base_name, "rt/ap/", 6) == 0) {
        hal.util->snprintf(buffer, buffer_size, "rt/ap_%u/%s",
                          instance, base_name + 6);
    } else {
        // Fallback - prepend instance to any topic
        hal.util->snprintf(buffer, buffer_size, "%s_%u", base_name, instance);
    }
}

void AP_DDS_Client::generate_service_name(char* buffer, size_t buffer_size,
                                         const char* base_name, uint8_t instance)
{
    // Replace "rs/ap/" with "rs/ap_N/" and "rq/ap/" with "rq/ap_N/"
    if (strncmp(base_name, "rs/ap/", 6) == 0) {
        hal.util->snprintf(buffer, buffer_size, "rs/ap_%u/%s",
                          instance, base_name + 6);
    } else if (strncmp(base_name, "rq/ap/", 6) == 0) {
        hal.util->snprintf(buffer, buffer_size, "rq/ap_%u/%s",
                          instance, base_name + 6);
    } else if (strncmp(base_name, "rr/ap/", 6) == 0) {
        hal.util->snprintf(buffer, buffer_size, "rr/ap_%u/%s",
                          instance, base_name + 6);
    } else {
        // Fallback
        hal.util->snprintf(buffer, buffer_size, "%s_%u", base_name, instance);
    }
}
```

void AP_DDS_Client::initialize_services(uint8_t instance_id)
{
    if (services_initialized) {
        return;
    }

    uint8_t service_index = 0;

#if AP_DDS_ARM_SERVER_ENABLED
    // Allocate dynamic name storage
    static char arm_service_name[64];
    static char arm_request_topic[64];
    static char arm_reply_topic[64];

    generate_service_name(arm_service_name, sizeof(arm_service_name),
                         "rs/ap/arm_motorsService", instance_id);
    generate_service_name(arm_request_topic, sizeof(arm_request_topic),
                         "rq/ap/arm_motorsRequest", instance_id);
    generate_service_name(arm_reply_topic, sizeof(arm_reply_topic),
                         "rr/ap/arm_motorsReply", instance_id);

    services[service_index] = {
        .req_id = to_underlying(ServiceIndex::ARMING_MOTORS),
        .rep_id = to_underlying(ServiceIndex::ARMING_MOTORS),
        .service_rr = Service_rr::Replier,
        .service_name = arm_service_name,
        .request_type = "ardupilot_msgs::srv::dds_::ArmMotors_Request_",
        .reply_type = "ardupilot_msgs::srv::dds_::ArmMotors_Response_",
        .request_topic_name = arm_request_topic,
        .reply_topic_name = arm_reply_topic,
        .qos = {
            .durability = UXR_DURABILITY_TRANSIENT_LOCAL,
            .reliability = UXR_RELIABILITY_RELIABLE,
            .history = UXR_HISTORY_KEEP_LAST,
            .depth = 5,
        },
    };
    service_index++;
#endif

    // Repeat for all services...
    services_initialized = true;
}

## Implementation Details

### Memory Management Strategy

**Challenge:** Dynamic string allocation for topic/service names
**Solution:** Static pre-allocated character arrays per topic/service

```cpp
// Memory allocation pattern for each topic
#if AP_DDS_NAVSATFIX_PUB_ENABLED
static char navsat_topic_name[64];
#endif

#if AP_DDS_IMU_PUB_ENABLED
static char imu_topic_name[64];
#endif

// Maximum name length: "rt/ap_99/imu/experimental/data" = 32 chars
// Buffer size: 64 chars provides safe margin
```

### Instance ID Resolution Priority

1. **Explicit Parameter:** `DDS_INSTANCE_ID` parameter value
2. **SYSID Auto-detection:** `SYSID_THISMAV - 1`
3. **Default Fallback:** `AP_DDS_DEFAULT_INSTANCE_ID` (0)

### Error Handling

```cpp
// Validation in detect_instance_id()
uint8_t instance = /* detection logic */;
if (instance > AP_DDS_MAX_INSTANCE_ID) {
    GCS_SEND_TEXT(MAV_SEVERITY_ERROR, "%s Instance ID %u exceeds maximum %u",
                  msg_prefix, instance, AP_DDS_MAX_INSTANCE_ID);
    instance = AP_DDS_DEFAULT_INSTANCE_ID;
}
return instance;
```

## Pattern Formation Control Benefits

### Individual Vehicle Control
```python
# ROS2 Python Control Example
import rclpy
from geometry_msgs.msg import TwistStamped

# Control vehicle 0
pub_0 = node.create_publisher(TwistStamped, '/ap_0/cmd_vel', 10)

# Control vehicle 1
pub_1 = node.create_publisher(TwistStamped, '/ap_1/cmd_vel', 10)

# Send different commands to each vehicle
pub_0.publish(velocity_cmd_leader)
pub_1.publish(velocity_cmd_follower)
```

### Formation Algorithms
- **Leader-Follower:** Leader on `/ap_0/*`, followers on `/ap_1/*`, `/ap_2/*`
- **Consensus-Based:** Each agent publishes state to unique namespace
- **Centralized Control:** Formation controller subscribes to all `/ap_N/pose/filtered`

## Backward Compatibility

### Default Behavior
- **Single Instance:** Uses traditional `/ap/*` namespace (instance 0)
- **Existing Code:** No modification required for single-vehicle use
- **Parameter Default:** `DDS_INSTANCE_ID = -1` (auto-detect)

### Migration Path
1. Deploy code with new parameters
2. Set `DDS_INSTANCE_ID = 0` for existing single-vehicle setups
3. Use `DDS_INSTANCE_ID = N` for new multi-vehicle configurations
4. Gradual rollout with fallback to original behavior
