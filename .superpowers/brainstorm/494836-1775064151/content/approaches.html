Orin Nano ↔ Cube Orange Integration: Approaches

How to structure the serial connection and camera pipeline on the Orin Nano

A

Direct Serial — Minimal Change

Connection: pymavlink opens /dev/ttyTHS1 directly at 921600 baud. Your mavlink_interface_node switches between TCP (sim) and serial (real) based on hardware_params.yaml.

Camera: Use nvarguscamerasrc via a GStreamer-based ROS2 camera node to publish to the same /camera/image topic the sim uses.

Pros: Fewest moving parts. No extra daemons. Lowest memory footprint (critical for 4GB).

Cons: Only one process can own the serial port — no QGC on a separate laptop unless you add a MAVLink router later. Single point of failure on the serial link.

Best for: Getting flying fast with minimum complexity.

B

MAVLink Router — Shared Link

Connection: Run mavlink-routerd on the Orin. It owns /dev/ttyTHS1 and exposes UDP endpoints. Your mavlink_interface_node connects via UDP localhost (same as it would in sim, just different address). QGC on a laptop can also connect over WiFi/Ethernet.

Camera: Same as A — nvarguscamerasrc via ROS2 camera node.

Pros: GCS operator sees live telemetry alongside autonomous operation. Familiar TCP/UDP connection for your node. Adds ~2MB RAM overhead.

Cons: Extra daemon to manage. Slightly more latency on MAVLink (negligible in practice). One more thing that can fail.

Best for: Competition day — your GCS operator needs telemetry access simultaneously.

C

Hybrid — Direct Serial Now, Router Ready

Connection: Implement direct serial in mavlink_interface_node (Approach A). Also add a connection_type field in hardware_params.yaml that supports tcp, serial, and udp. When you need QGC access later, drop in mavlink-routerd and switch to UDP — no code changes.

Camera: Same — nvarguscamerasrc via ROS2 camera node.

Pros: Fly and test immediately with serial. Upgrade to router when needed without touching your node code. Maximum flexibility.

Cons: Slightly more config parameters upfront. Need to test both serial and UDP paths.

⟵ Recommended

Common to All Approaches

Physical Wiring Cube Orange TELEM2 TX/RX/GND → Orin Nano UART1 (J12 header pins 8/10/GND). 3.3V logic on both sides — no level shifter needed.
TELEM2 Params SERIAL2_BAUD=921, SERIAL2_PROTOCOL=2 (MAVLink2)
Orin UART Setup sudo systemctl stop nvgetty, sudo usermod -aG dialout $USER, device appears as /dev/ttyTHS1
Camera Arducam IMX219 via CSI → nvarguscamerasrc (hardware ISP) → ROS2 image_transport
Memory Budget (4GB) ~600MB JetPack overhead + ~400MB ROS2/nodes + ~200MB camera pipeline + ~100MB apriltag = ~1.3GB. Leaves ~2.7GB headroom.
